OMI · information architecture · design reference

From ~30 tabs a page to one readable path.

Before we touch the visual language, this fixes the structure underneath it. One rule does the work: stop using tabs for everything. Sort every tab into one of three kinds and give each the container it actually wants. The result — every suite collapses onto the same short spine.

1

The method — three questions

Ask this of every current tab. The answer decides where it lands and what shape it takes.

Do I look at it?

A read-out — ranks, coverage, ROAS. These get scanned together, so they belong on one dashboard, not N tabs.

▦ Dashboard
Do I work through it?

A process done in order — brief → draft → ship. That's one stepper guiding you, not 5 sibling tabs.

→ Stepper
Do I dip into it?

Independent tools you reach for occasionally. One accordion / launcher — pick one, run it, move on.

▾ Accordion
Merge test — combine things you'd consult in the same sitting; keep apart things that are different sessions. A single 30-accordion mega-page just trades click-overwhelm for scroll-overwhelm.

The payoff — one spine, everywhere

Every suite lands on the same two constants — Health (look) and Build (make & ship) — plus a short tail of channel-specific verbs. Learn the shape once; it holds in every channel. That sameness is the cohesion you were missing between Owned, Shared and Paid.

Each suite still opens on its Overview. Health is a noun (read); every other page is a verb (do) — the naming carries the read-vs-do line. Once this lands, the action-grammar mockup applies on top: on any page there's far less to rank, because there are only a handful of things on it.

Notes for the build

Sequence
  • Land the IA first (this doc), then the action grammar on top.
  • Do Owned end-to-end as the pattern; confirm Paid / Earned / Shared, then repeat.
  • Ship page-by-page — Owned Health first (pure consolidation, low risk).
Reuse / borrow
  • Containers already exist: ProcessRail / Stepper (steppers), SuiteTabs (the ≤6 top nav).
  • Accordion is the one new primitive — build it in OMI's own CSS tokens.
  • Borrow only the a11y patterns from @astryxdesign/core (focus mgmt, ARIA) — no dependency, no StyleX, no React 19.
  • Gate Local on the client's local-business flag.

House style unchanged — OMI tokens throughout; real app uses Brockmann. Badges (▦ → ▾) mark container type, the one new idea this doc adds.
