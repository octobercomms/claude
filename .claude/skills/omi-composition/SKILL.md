# The OMI Composition, by hand

One Composition in, one ffmpeg `filter_complex` out. The same object drives the
browser preview, so anything you write here is what the export produces — that
agreement is the guarantee the whole model is built on, and several of the
faults below were the agreement quietly broken.

Everything is in `dev/platform/shared/`. **Read the code for the field lists;
read this for the rules the code cannot tell you.**

| What | Where |
|---|---|
| The model and `validate()` | `composition.mjs` |
| The published JSON Schema, generated from it | `composition.schema.json`, built by `compositionSchema.mjs` |
| The ffmpeg graph | `compositionRender.mjs` |
| The browser preview | `compositionPlayback.mjs`, `frontend/src/components/video/Compositor.jsx` |
| Templates, motions, variation | `compositionTemplate.mjs`, `templates/*.json` |
| Caption presets (31) and the ASS compiler | `captions/presets.json`, `captions/compile.mjs` |
| Effects (3) | `compositionFx.mjs` |
| Batch pre-flight, QC, reference reading | `compositionBatch.mjs`, `renderQc.mjs`, `referenceAnalysis.mjs`, `captionMatch.mjs`, `structureLabel.mjs` |

## The shape

```json
{
  "version": 1,
  "size": { "width": 1080, "height": 1920 },
  "fps": 30,
  "ducking": false,
  "sources": { "<id>": { "kind": "...", "...": "..." } },
  "tracks": [ { "id": "t0", "kind": "video", "items": [ ... ] } ]
}
```

- `version` must be `1`. `validate()` refuses anything else rather than
  guessing at an older shape.
- `fps` is 1 to 120. `size` must be positive. Both are the frame the whole
  graph is built against: an effect's mask, a caption's margin and a
  transform's travel are all fractions of it.
- `ducking: true` compresses the music under the voice with
  `sidechaincompress`. It needs both a voice and something else, and which is
  which is a fact about the **source**, not its kind — see the invariants.

## Sources

`SOURCE_KINDS` in `composition.mjs` is the list. Each needs different things:

| kind | needs | notes |
|---|---|---|
| `clip` | `asset` or `url` | footage, or a photograph with `still: true` |
| `design` | `project` | a design page, drawn as a still image with alpha |
| `audio` | `asset` or `url` | music or narration |
| `captions` | `transcript` | **not footage**; see the invariants |
| `fx` | `effect` | generated by ffmpeg: `scrim`, `vignette` or `rule`, which is `FX_NAMES` |

Optional on a `clip`: `still`, `voice`, `duration`, `width`, `height`, `fps`.
Optional on `audio`: `voice`, `duration`. Optional on `captions`: `template`
(a preset id), `perLine`. Optional on `fx`: `params` (validated against the
effect's own list in `compositionFx.mjs`), `duration`.

## Tracks and items

Tracks composite in array order: track 0 is the base, each later one over it.
`kind` is `video` or `audio`.

An item is an `id`, an `at` (where it starts on the timeline, in seconds), a
`len` (how long it runs) and a `source`, plus any of:

| field | range | what it does |
|---|---|---|
| `in` | ≥ 0 | where to start inside the source |
| `fit` | `cover`, `contain` | how to fill the frame |
| `gain` | 0 to 4 | audio level |
| `opacity` | 0 to 1 | layer opacity, and the strength dial on an effect |
| `trans` | `{ type }` from `TRANSITION_TYPES` | a transition **into** this item |
| `beat` | a name from `MOTION_NAMES` | which camera move this is, for the review sheet |
| `scale` | 0.01 to 10 | a number, or `{ from, to }` to animate |
| `pos` | −2 to 3 | `{ x, y }` as fractions of the frame, or `{ from, to }` |
| `rot` | — | validated and **not rendered**; see the invariants |
| `reason`, `quote` | ≤ 500 chars | why this item is here. The renderer ignores them |

## The invariants

These are the rules `validate()` cannot express, every one of which has cost a
broken render in this repo.

**1. Captions are a filter, not an input.** A `captions` source becomes a
single `subtitles=` filter fed by a compiled ASS file. It has no asset, so as
an ffmpeg input the route answers `Source "x" has no file on disk` — and if a
path did exist, the words would be burned twice. A caption item sits on a
track so the editor can show where the words are, and `renderGraph` skips it
in the input loop.

**2. One caption source per composition.** The renderer burns one ASS track;
`buildCaptionAss` throws on a second. Several caption ITEMS pointing at one
source is right and normal — see `stills-with-type.json`, where two titles
share one source.

**3. A photograph needs `still: true`.** A still has no audio stream, so
emitting `[n:a]` for it makes ffmpeg refuse the entire `filter_complex` with
"matches no streams"; and a one-frame input needs `-loop 1 -t <len>` or it
contributes one frame and the picture flashes rather than holds. Default
false, so a clip that does not say it is a still is treated as footage.

**4. An `fx` source generates itself.** No asset, no url. `renderGraph` marks
it `generated` with a lavfi filtergraph, and `ffmpegArgs` emits
`-f lavfi -i <graph>` instead of `-i <path>`. Its slot in the resolved-paths
array is kept (as `null`), because ffmpeg numbers `[n:v]` by position and
dropping an entry points every later input at the wrong file.

**5. A transition is an OVERLAP.** `trans` on an item means it crossfades with
the item before it on the same track, so that item must START BEFORE the
previous one ends. No overlap, no transition, whatever `trans` says.

**6. A picture cannot sit on an audio track**, and an audio source cannot sit
on a video track. `PICTURE_KINDS` is the list the validator checks.

**7. The voice is a property of the source, not its kind.** `voice: true`
marks the thing everything else ducks under. A talking head's voice is a
`clip`; a walkthrough's is an `audio` narration while the clips are silent
b-roll. Guessing from the kind ducks a walkthrough's narration under its own
room tone, which is backwards.

**8. `rot` validates and then refuses to render.** The model accepts it, and
`renderGraph` throws rather than dropping it: `rotate`'s output box is
init-only, so an animated rotation needs a constant box sized for the maximum
angle, which is not built. The preview does not draw it either. An honest
refusal, because a transform the renderer silently ignored would be the
preview and the export disagreeing — do not put `rot` on an item you intend
to render.

**9. Colours in a caption preset are authored as hex and converted to ASS's
BGR by the compiler.** Do not pre-swap them.

**10. `dissolve` is a transition the templates may not use.** Despite the name
it is a per-pixel random-threshold dither, and the noise it makes is
uncompressible: the same 11-second reel measured 6.24MB with `dissolve`
against 0.54MB with `fade`.

## The schema, and what a schema cannot tell you

`shared/composition.schema.json` is draft 2020-12 and is **generated** from
`composition.mjs` by `compositionSchema.mjs` — every vocabulary and every
bound in it is read out of the model rather than typed again, and a test
regenerates it and fails if the committed file has drifted. Point a tool at
it; do not edit it.

It describes the **shape**. It cannot describe the rules that span more than
one part of the document, and those are most of the invariants above: a
picture on an audio track, a second caption source, an item referencing a
source that is not there, a transition with no overlap behind it. A green
tick from the schema is not "this will render". `validate()` is the next step
and the graph is the one after that.

## How to check your work before spending an encode

```bash
cd dev/platform
node -e "import('./shared/composition.mjs').then(m=>console.log(m.validate(require('/path/to/comp.json'))))"
```

An empty array means valid. Then build the graph, which is where the
invariants above bite:

```bash
node -e "Promise.all([import('./shared/composition.mjs'),import('./shared/compositionRender.mjs')]).then(([c,r])=>{const comp=require('/path/to/comp.json');console.log(c.validate(comp));const g=r.renderGraph(comp,{captionAssPath:'/tmp/x.ass'});console.log(g.inputs.length,'inputs');console.log(g.graph)})"
```

Then the suites that cover what you touched:

```bash
cd dev/platform/backend && node tests/composition-render.test.js
```

```bash
cd dev/platform/backend && node tests/composition-render-pixels.test.js
```

**A graph-level check is not enough on its own.** Every render guard in this
repo once asserted on the `filter_complex` string, and that is how a correct
string referencing a stream that does not exist reached production twice. If
you change what reaches ffmpeg, add a pixel assertion — there are three files
of them (`composition-render-pixels`, `template-render-pixels`,
`composition-fx-pixels`) and they render real frames and sample them.

## Worked examples

All four are in `assets/`, and `backend/tests/composition-skill.test.js`
asserts that each one validates and builds a graph. An example here cannot
rot without CI failing.

| File | What it shows |
|---|---|
| `hard-cut.json` | the simplest edit: two clips, no transition, `in` points, `reason` on each item |
| `stills-with-type.json` | photographs with `still: true`, animated `scale` and `pos`, fades as overlaps, ONE caption source with two placements, a music bed |
| `talking-head-ducked.json` | `ducking: true` with `voice: true` on the clip and `voice: false` on the bed, and captions resolved from the clip's own transcript |
| `scrim-under-type.json` | a generated `fx` layer between the photograph and the words |

## Writing a template rather than a composition

A template in `templates/*.json` is bound to content by `bindTemplate`. It is
a different schema — slots, not items — and `validateTemplate` enforces it.
Two rules carry most of the weight:

- **A template may declare only the fields the binder reads.** A test fails on
  anything else, because a template is data nothing compiles and a field the
  binder ignores is a claim nobody implements.
- **A slot's `len` is a range and the binder takes the midpoint**, jittered per
  item so a batch of thirty does not march in step. Transitions come out of
  that length as overlaps, so the sum of the slot lengths is always longer
  than the finished timeline.
